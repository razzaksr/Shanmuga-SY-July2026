		Inheritance: Is A Relationship
			extend the object reusability to another level
			using one class's object we can access members of many class's only if they had "is a 							relationship"/ inheritance
			
			eg: Gmail>> super/ base/ parent class;
				Gmail>> class
					send, draft, ....
				Youtube>> class is a relation with Gmail; Youtube is derived/ child class
					playlist, upload,
				Playstore>> class is a relation with Gmail; Playstore is derived/ child class
					Download, share
				Maps>> class is a relation with Gmail; Maps is derived/ child class
					saved location, share, directions
				
				one Gmail account/object is enough to access other Apps/class
				
			apply inheritance:
			1. extends >> is a relation>> DerivedClass extends BaseClass

			types:
				Single, multi level, hierarchy, hybrid, multiple
			
			Runtime/ Dynamic Polymorphism/ Overriding:
			happens between class's those were involved in inheritance
				writing base class's method again in derived class for 						writing own definition/ logic
				eg: Transfer in Bank is not same Transfer in the Wallet, 				Transfer in the ATM and Transfer in the InternetBanking

			Note: 
				Non Abstract method: method with definition ({})
				Abstract method: method without definition ({})

				Overriding is not mandate on non-abstract method
				Overriding is mandate on abstract method


			Abstraction:
				Hide the definition/ logic of the method/ abstract method
				the following components in those write abstract methods
				1. Abstract Class
					cannot create object so access via inheritance
					override when it has abstract method
				Note: Abstract methods has to be overridden in their 						derived component

				2. Interface:
					just like class component with certain difference
					it can't be instantiated
					data members need to be initialized
					DerivedClass implements Interface
					data members in interface are final(can't modify)							only contains abstract methods eventually it has to be 							overridden by derived class

				Functional Interface:
					we can use lambda for interface which has 								only one abstract method

					Advantage:
						1. No need derived class
						2. No need to override
						3. Creating object directly

					Limitations:
						1. interface should have only one abstract method
						2. cannot access data members if present unlike 								when we implements

			Exception Handling:

			Error: 
				Compile time error: logical, syntax
				Runtime error: cannot be handled, mostly happens due to non 							coding parameters
				eg:
					Bank server down, even though UPI works good
			Exception: code
				condition/ statement which lead the program/app terminates 								abnormal/incomplete
				it can be handled
				eg:
					Invalid UPI pin while transfer

			Objective of handling: enhance the customer experience by 
				1. let the code complete 
				2. Provide another chance>>(catch block)

			types:
			1. Compile/ Checked Exception: while compile the code itself identify and 				handle
				eg: 
					IOException>> java.io
					InterruptedException
					
			2. Runtime/ Unchecked Exception: while running the code only we can 				identify later we handle
				eg:
 					NullPointerException
					ArrayIndexOutOfBoundsException
					InputMismatchException>> java.util
					NumberFormatException
					ArithemeticException

			How to handle:
			1. try .... catch... finally
			
				try{
					// statement possibly raise exception
				}catch(ExceptionClass objext){
					// handle giving another chance
				}finally{
					// executes irrespective exception occurred or not
				}

				if exception occurred in try >> catch>> finally
				if exception not occurred in try>> finally

			2. throws>> keyword
				simply handle the exception, no place to offer another chance/fixing mistake
				mention "throws" at signature/beginning of the method

			Approaches:
				1. handling in the same try catch for 1 time
				2. handling in the same try catch for fixed amount of times
				3. handling in the same try catch for infinite number of times
				4. handling in the caller/main try.. catch using "throw" keyword, since its used to 						forward exception from one block to another
				5. handling multiple exceptions in single catch only if solutions for both is same
				6. handling multiple exceptions in different catch block since each catch block 							offers different solution
				7. handling exception inside another catch
